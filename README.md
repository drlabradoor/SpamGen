# SpamGen

Генератор скриншотов списка чатов Telegram — iOS 26 Liquid Glass, тёмная тема,
iPhone 13 (1170×2532 @3x). Все константы сняты пиксельными замерами с настоящих
скринов, а не подобраны на глаз.

## Запуск

```bash
node tools/selftest.js          # проверка рендера
node tools/render-cli.js out/demo.json out/my.png
node bot.js                     # бот (нужен токен)
```

Токен кладётся в `.env`:

```
SPAMGEN_TOKEN=123456:AA...
```

Зависимостей нет вообще — ни одного npm-пакета. Нужен только Node ≥ 20 и
бинарник Chromium. Путь ищется сам (`src/chromepath.js`): `SPAMGEN_CHROME`,
затем самый свежий билд из кэша playwright, затем установленный Chrome /
Chromium / Edge, в Docker — `/usr/bin/chromium`. Хардкода пути больше нет:
playwright удаляет старые билды при обновлении, и рендер падал с ENOENT.

## Команды бота

| Команда | Что делает |
|---|---|
| `/new` | новый экран: имена → сообщения → диапазон времени → аватарки (цифрой с Пинтереста или альбомом) |
| `/add` | добавить одного человека пошагово |
| `/edit` | список людей на экране, правка каждого |
| `/render` | собрать |
| `/random 8` | заполнить случайными и сразу собрать |
| `/settings` | настройки рандома и запросы для аватарок |
| `/addava` | пополнить банк аватарок — дальше просто шлёшь фото. Банк работает только в `/add` и `/random`, в `/new` его нет |
| `/addstatus` | пополнить банк премиум-статусов — шлёшь эмодзи |
| `/reset` | сбросить |

### Основной поток

`/new` спрашивает три текстовых блока подряд, каждый одним сообщением:

```
Артём              привет!                    09:00 21:00
Кирилл             актуально ещё?
Дарья              скинь реквизиты
```

и четвёртым шагом — **аватарки**: цифра 0–10 или свой альбом до 10 фото.

Цифра `N` — бот сам ищет картинки на Пинтересте. Экран собирается сразу, из
всех строк (автодобор тоже) случайно выбираются `N`, и по ним сверху вниз
приходит кандидат: готовая строка списка с этой картинкой и подписью
`Дарья · 2/6`. `✅` — ставит, `❌` — следующий кандидат, `⏹ хватит` — остальным
буквы. Можно прислать своё фото — встанет текущей строке. `0` — все буквами.

Поиск идёт через внутренний эндпоинт pinterest.com (официальный API v5
публичного поиска не даёт), без логина. Запросы — в `/settings` → «🔎 Запросы»:
по умолчанию двенадцать, от «аватарки для тг» до «картины аватарка», чтобы на
экране были не одни лица. Показанный пин не показывается больше никогда —
`data/pins-seen.json`. Альбом, присланный фото, работает как раньше:
Telegram не помечает последнее фото альбома, поэтому он считается собранным,
когда 2 секунды не приходит новых.

Дальше экран собирается сам и больше не меняется без спроса:

- **аватарки** — фото из альбома раздаются случайным строкам, по одному на
  строку, автодобор тоже участвует. Десяти хватает на весь экран; если меньше —
  остальные строки получают инициал на градиенте, и бот говорит, сколько их.
  Больше десяти — берёт первые десять. Фото лежат в `data/album/<chat>/` и живут
  до следующего `/new`; «🎲 Пересобрать» раздаёт тот же альбом заново. Экран,
  собранный цифрой, пересборка людей не меняет: имя, текст, аватарка и поисковая
  строка остаются, перетасовываются времена, бейджи, премиум, батарея

- **времена** — края диапазона закреплены: верхняя строка садится на конец,
  нижняя из твоих на начало, остальные падают между случайно. Одинаковые времена
  допустимы; `normalize()` всё равно сортирует, так что новое никогда не окажется
  ниже старого
- **непрочитанные** — бейдж 1-3 на каждой твоей строке
- **премиум** — 20% строк, из них 60% со статусом из банка, остальные с обычной
  синей звездой
- **автодобор** — если имён меньше, чем влезает на экран, низ добивается
  случайными: имена и тексты без повторов (в том числе с твоими), времена уходят
  ниже начала диапазона, бейджи вперемешку с галочками
- **рассинхрон** — сообщений меньше имён, доберёт из встроенных и скажет; больше
  — отбросит лишние и скажет; имён больше вместимости — обрежет снизу

Собранный экран **заморожен**: повторный `/render` даёт тот же файл. Заново
рандомит только кнопка «🎲 Пересобрать».

### Редактор

«✏️ Редактировать» → список строк (`·` помечает автодобор) → карточка человека:
премиум, статус, онлайн, мьют, закреп, бейдж, галочка, аватарка, имя, текст,
время. Аватарка в карточке — «🔎 Найти», «📷 Своё фото» или «🔤 Буква».
«Найти» — тот же отбор ✅/❌ с Пинтереста для одной строки; своё фото
кладётся к альбому экрана, не в банк. «🖼 Собрать» подменяет превью на месте через `editMessageMedia`, так что
десять правок не оставляют в чате десять картинок. Чистый PNG — по кнопке
«📄 PNG».

### Банк статусов

`/addstatus` принимает и обычные эмодзи, и кастомные. Обычные тянутся из
Apple-набора тем же кэшем, что и эмодзи в тексте. Кастомные приходят как
`MessageEntity` с `custom_emoji_id` (боту для чтения премиум не нужен, он нужен
только тому, кто их шлёт) и подтягиваются через `getCustomEmojiStickers`:
статичные — сам `.webp`, который Chromium рендерит нативно, анимированные и
видео — их статичный `thumbnail`. Повторы статуса на одном экране разрешены.

Кнопка «😀 статус» в карточке показывает, что стоит сейчас, и открывает выбор:
кнопка на каждый глиф из банка. Обычные эмодзи рисуются на кнопке сами собой,
кастомные нумеруются — нарисовать кастомный эмодзи на кнопке нельзя, для этого
нужен премиум, а у бота его нет. Там же «✖️ убрать» и «➕ новый» — второй ждёт
эмодзи и ставит его этому человеку, попутно кладя в банк.

Старый пошаговый визард никуда не делся и живёт под `/add`:
имя → сообщение → время → **аватарка** → флаги кнопками
(премиум, онлайн, мьют, закреп, счётчик непрочитанных или галочка).

Шаг аватарки:

| Кнопка | Что делает |
|---|---|
| 🎲 Из банка (N) | берёт случайную из `assets/bank`, без повторов внутри экрана. Показывается только когда банк не пуст |
| 📷 Своё фото | ждёт фото, ставит его этому человеку и **кладёт в банк** — банк растёт сам по себе |
| 🔤 Буква | инициал на фирменном градиенте, цвет по хешу имени |

Если ничего не выбрано (например, строка пришла из `/random`), аватарка
назначается сама: три четверти из банка, четверть буквами.

Результат приходит дважды: `sendPhoto` для быстрого просмотра и `sendDocument`
с чистым PNG — Telegram пережимает фото в JPEG и убивает хайрлайны в 1px.

### Тесты

```
node tools/selftest.js     рендер демо-конфига: размер, профиль, эмодзи
node tools/flowtest.js     основной поток целиком + альбом + редактор + банк статусов
node tools/wizardtest.js   пошаговый /add
node tools/banktest.js     ветка «из банка»
node tools/pinsunit.js     src/pins.js: фильтр, листание, seen, отказы
node tools/rowtest.js      превью строки: 1170×228 и быстрее 1.5 с
node tools/pinstest.js     отбор с Пинтереста через бота, запросы, «Найти», пересборка
```

Все они гоняют настоящий рендер, но сеть застаблена, а состояние, банк аватарок,
альбомы, банк статусов и список показанных пинов подменяются на временные через
`SPAMGEN_STATE`, `SPAMGEN_BANK`, `SPAMGEN_ALBUM`, `SPAMGEN_STATUS` и
`SPAMGEN_PINS_SEEN` (`SPAMGEN_ALBUM_MS` ужимает ожидание конца альбома).
Пинтерест в тестах — `tools/fakepins.js` поверх `globalThis.fetch`. Это не косметика: `banktest` раньше стирал `assets/bank`
целиком, чтобы засеять свои тестовые аватарки, и один запуск уносил всё, что
было собрано.

`tools/recover-avatars.js` вытаскивает аватарки обратно из готовых рендеров в
`out/` — в них аватар нарисован ровно в 180×180, то есть в том же размере, в
котором его рисует генератор.

### Цвет

Скрины с iPhone идут в **Display P3**, а Chromium рендерит в sRGB. Поэтому в CSS
лежат сырые P3-значения, снятые с эталона, а после рендера в PNG вшиваются чанки
`iCCP`/`cICP`/`pHYs` из `assets/p3-chunks.bin`. Без этого картинка выглядит
заметно бледнее настоящей.

### Шрифты

`assets/fonts/` — SF Pro, бандлится в репозиторий и никогда не берётся из системы.
Всё — SF Pro Display, включая кириллицу.

### Эталоны

`ref/IMG_premium.PNG` — **актуальный**, по нему откалибровано всё.
`ref/IMG_6260.PNG` и `ref/IMG_6264.PNG` — более старая сборка Telegram: там
другая строка папок и шрифт примерно на 8% мельче при той же капители.
Замеры оттуда мешать с новыми нельзя — из них взяты только спрайты иконок
(галочки, пин, мьют, элементы хрома), которые не поменялись.
`ref/IMG_6276.PNG` — тот же билд, экран каналов: восемь переносов превью, куча
трёхзначных бейджей и styled-Unicode в названиях. По нему меряется ширина превью
и собирается реплика `out/replica3.json`.
`ref/IMG_6280.PNG` — тот же актуальный билд, но с **очищенными бейджами** на

Settings: на всех остальных эталонах поверх них лежит красная капсула, и вырез
под неё съедал верх пузырей (`tools/key6280.js`, `tools/rip-me.js`).

### Поля строки

`name` `text` `time` · `badge` или `check` (1/2) · `premium` `mute` `online` `pin`
· `photo` (аватарка) · `letter` (инициал вместо фото) · `ring` (непросмотренная
история) · `thumbs` (массив картинок перед текстом превью).

Эмодзи в имени — не часть текста, а соседние флекс-элементы: Telegram обрезает
слова троеточием, но эмодзи не режет никогда, и порядок сохраняется, так что
ведущее «📊 Signals2Trade» остаётся ведущим. Символы `™ © ®` в эмодзи не
превращаются — у них текстовое представление по умолчанию, и подстановка
картинки красит их в чёрный; вместо этого они рисуются мельче и тусклее, как в
оригинале.

### Инварианты

`src/model.js` не даёт экрану противоречить самому себе:

- времена строго по убыванию, закреплённые вне сортировки;
- часы в статус-баре на 1–3 минуты позже верхнего чата;
- бейдж непрочитанных и галочка взаимоисключающи;
- у закрепа пин прячется, когда есть непрочитанные;
- список всегда уходит за нижний край: строк ровно столько, чтобы нижняя
  обрезалась краем экрана, а из-под таб-бара торчал ещё один чат. Список,
  кончающийся ровно по границе строки, читается как «у человека девять чатов» —
  и как подделка. Бот добирает недостающие строки сам, ниже самой старой;
- имена и тексты в доборе тянутся **без повторов**: одно имя дважды даёт тот же
  градиент и ту же букву — выглядит как один человек продублирован, а
  повторившаяся строка превью видна сразу;
- бейдж на «Chats» считается от списка, а не задаётся руками: это **сумма
  непрочитанных сообщений** по незамьюченным чатам (так считает сам Telegram по
  умолчанию), а не число чатов с непрочитанным;
- к этой сумме идёт **случайная накрутка +40…180 %** — на экран влезает девять
  строк, а у живого аккаунта непрочитанное есть и ниже, так что бейдж всегда
  больше пересчитываемого. Накрутка пропорциональная, поэтому тихий экран не
  заявляет вдруг сотни. Пересчитывается на каждом рендере, как часы и батарея;
  `tab.inflate:false` прибивает бейдж ровно к видимому, `tab.chats` — к своему
  числу. Пустой список непрочитанных остаётся без бейджа: прочитанный верх при
  непрочитанном низе означал бы список не по времени.

## Деплой на bothost.ru

Тариф Pro (4 vCPU / 2 GB / 15 GB) с кастомным Dockerfile. Загрузка — архивом
`spamgen-bothost.zip` (или git), в настройках бота включить «Использовать
собственный Dockerfile». Токен берётся из `SPAMGEN_TOKEN`, `TELEGRAM_BOT_TOKEN`
или `BOT_TOKEN` — последние bothost выставляет сам. Один инстанс Chromium на
процесс — второй не влезет в 2 ГБ, поэтому `src/render.js` держит очередь.

Между обновлениями bothost сохраняет только `/app/data`. Поэтому в контейнере
банк аватарок и статусов живёт в `data/bank` и `data/status` (`start.sh` один
раз копирует их из `assets/`), там же сессии, альбомы и `pins-seen.json`.

Один токен — один потребитель `getUpdates`: пока бот крутится на сервере,
локальный `node bot.js` должен быть выключен, иначе оба ловят 409 Conflict.

## Известные расхождения

- Хвост `Q` короче эталонного на 6px — зеркало SF Pro старше версии из iOS 26.
- Иконки статус-бара (геострелка, 4G) взяты со старого эталона. На новом у
  владельца wi-fi и режим сна — если нужен именно такой набор, вырезать спрайты
  из `ref/IMG_premium.PNG`.
- **Наш SF Pro шире айосовского примерно на 1.5%.** «PRESS HERE FOR FREE ACCESS
  TO» из `ref/IMG_6276.PNG` набирается на 11 device px шире оригинала. Из-за этого
  настоящий правый край превью (он не фиксированный: Telegram держит зазор до
  бейджа, и обрезанные строки эталона доходят до x986-998) воспроизводить нельзя —
  с ним в строку влезает слово, которое iOS перенёс. Оставлено 982: оно съедает
  разницу и повторяет переносы эталона. Проверено — 994, 1004 и 1008 дают хуже.
- **Обрезка последней строки превью идёт по слову, а не по букве.** iOS дорезает
  строку посимвольно («работаем с кр…»), `-webkit-line-clamp` в Chrome ставит
  многоточие после последнего целого слова («работаем с …»). Разница — 40-70
  device px на строку. Чинится только предрасчётом обрезки в два прохода.
- **Кастомные эмодзи Telegram не воспроизводятся.** В `ref/IMG_6276.PNG` превью
  пятой строки начинается с глифа «24 в круге со стрелкой», перекрашенного в цвет
  текста (`#8d8e92`) — у него нет кодовой точки, подставить из Apple-набора нечего.
- Названия каналов часто написаны styled-Unicode (`𝐗𝐀𝐔𝐔𝐒𝐃`, `𝖫𝗂𝗊𝗎𝗂𝖽𝗂𝗍𝗒`): и iOS, и
  Chrome уводят их в запасной шрифт, но в разный — ширина расходится на 5-6%.
  В таких прогонах ™ рисуется целиком и белым, а не мельче и тусклее, как делает
  `.sym` для обычного SF Pro.
- Аватарка живёт только на вкладке Settings, в шапке её нет (там она рисовалась
  бы кольцом непросмотренной истории, которого на эталоне нет). По умолчанию
  пустая, задаётся через `chrome.avatar` — рендер сам переносит её на таб.
- Бот снимает **пролистанный** список (`chrome.search:false`): так сняты все
  эталоны, и это те самые 162 device px, которые отделяют девять строк от
  десяти. Вернуть строку поиска — убрать `search:false` из `SHOT` в `bot.js`.
